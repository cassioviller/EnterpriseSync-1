# Cronograma — Padrão de Revisão

Este capítulo é a **norma** do cronograma. O capítulo anterior ensina onde
clicar; este define **quando mexer, o que fica registrado e o que não é aceito**.

Ele existe porque o cronograma é o único documento da obra que três pessoas
mexem por motivos diferentes: o planejamento reprograma, o campo aponta, o
comercial adita. Sem regra, as três edições viram a mesma coisa na tela — e
seis meses depois ninguém consegue responder por que a obra atrasou.

## O vocabulário da tela

Cinco colunas dizem coisas diferentes sobre a mesma tarefa. Confundi-las é a
origem de quase toda discussão:

| Na tela | O que é |
|---|---|
| **Início (plan.)** e **Término (plan.)** | As datas **vivas**. São estas que se movem durante a obra. É o cronograma que vai ao cliente. |
| **Linha de base** | As datas **congeladas** de uma revisão aprovada. Não se movem. |
| **% Realizado** | O avanço apurado pelos apontamentos do RDO. Ninguém digita. |
| **% Planejado** | O avanço que era esperado **hoje**, calculado linearmente pelas datas da tarefa. |
| **Desvio** | Término vivo menos término congelado. É o atraso contra a linha de base ativa. |

## 1. A primeira linha de base

**Assim que o cronograma é aprovado, congele-o** no botão **Linha de base**.
Ela nasce como **V1**.

- Antes disso a coluna **Desvio** não existe — não há contra o que comparar, e
  a obra roda cega.
- Congele o cronograma **aprovado**, não o rascunho de estudo.

**Não é aceito:** obra em execução sem linha de base.

## 2. O planejado se move; a linha de base não

Durante a obra, o que muda são **Início (plan.)** e **Término (plan.)**.
Painelizaria dia 2 e painelizou dia 4? Mova a data. É para isso que ela existe.

A linha de base **fica onde está**. É dela que sai o Desvio — e é o Desvio que
mostra, sem discussão, que aqueles dois dias aconteceram.

**Não é aceito:** congelar uma linha de base nova para fazer o atraso
desaparecer. Isso não corrige o prazo, apaga a prova dele.

## 3. Quando abrir uma revisão nova

Uma revisão nova (**V2**, **V3**…) só se abre quando **o contrato muda**:
aditivo, supressão ou mudança formal de escopo.

- **Escreva o motivo.** O campo existe e é ele que sustenta a conversa lá na
  frente. "V2" sem motivo é um número sem história.
- **Atraso não é motivo de revisão.** Atraso se mostra no Desvio.
- **Replanejamento interno não é motivo de revisão.** Isso é mover o planejado.

Quem decide revisar é quem responde pelo contrato — a decisão não é automática,
e o sistema não a toma sozinho de propósito: aprovar um aditivo **não** cria
linha de base nova.

**Não é aceito:** revisão sem motivo escrito.

## 4. O histórico é o que dá a resposta

Cada linha de base fica guardada com seu número e seu motivo. Duas revisões
podem ser comparadas lado a lado, tarefa por tarefa, com o desvio entre elas.

É isso que permite dizer, com documento na mão: *"a entrega era dia tal; com o
aditivo, passou para tal"* — para o cliente e, antes dele, para dentro de casa.

**Não é aceito:** apagar uma revisão para "limpar" o histórico.

## 5. O percentual do grupo — a regra que confunde

O percentual de uma fase (tarefa-mãe) **não é digitado**: é calculado a partir
das filhas, por **média ponderada pela duração** de cada uma.

Isso tem uma consequência que parece defeito e não é. Numa fase de ~300 dias
que está em 98%, inserir 5 tarefas novas de 1 dia cada leva a fase para
**96,4%** — e não para ~80%. As 5 tarefas novas pesam 5 dias contra 300; a
matemática está dizendo que elas são pequenas, não que o cálculo falhou.

Se o número que se quer é "quantos itens da lista já terminaram", esse é outro
indicador, e não é este.

**Não é aceito:** apontar avanço na tarefa-mãe. Ela é sempre calculada.

## 6. Predecessoras

A coluna **Pred.** liga uma tarefa à que a antecede. Quando a antecessora se
move, quem depende dela se move junto.

Preencha a predecessora nas tarefas que de fato dependem de outra. Cronograma
sem ligação nenhuma vira lista de datas soltas: mover uma tarefa não avisa
ninguém, e o atraso só aparece no fim.

## O que o escritório confere

Um cronograma é devolvido para correção quando:

1. a obra está em execução e **não tem linha de base**;
2. existe **revisão sem motivo** escrito;
3. a linha de base foi **recongelada** e o desvio acumulado sumiu junto;
4. há **avanço digitado na tarefa-mãe** em vez de apontado nas filhas;
5. as datas vivas **nunca se moveram** numa obra que já acumulou atraso no
   RDO — cronograma que não é reprogramado não é cronograma, é enfeite.
